# Security Policy

## Reporting

Use GitHub private vulnerability reporting for suspected vulnerabilities. Do
not open a public issue before coordinated disclosure. Include affected
versions, a minimal reproduction, impact, and any known mitigation.

## Supported versions

No public version is supported during private incubation. Each public release
will publish its support state and affected conformance claims explicitly.

## Response and release safety

A credible identity, traversal, evidence-integrity, replay, authorization,
false-pass, or supply-chain issue stops the affected publication and promotion.
Published artifacts are never overwritten or unpublished as a repair. We fix
forward, publish affected-version guidance, and preserve historical decoding.

Portable-bounded conformance does not claim confidentiality against a hostile
same-OS-user process or hardened filesystem containment. Such guarantees require
a separately admitted profile and threat model.
